# ToB 客户开发 Skill

**把公开项目证据，转成销售团队能接手的客户开发决策。**

适用于按行业和地区开发企业客户、集成商或渠道伙伴。交付不止是一份名单：每个候选都有证据、优先级、接触理由和下一步，也能看出哪些判断还缺依据。

| 环节 | 团队拿到什么 |
| --- | --- |
| 市场筛选 | 目标市场、候选角色和匹配依据 |
| 接触策略 | 围绕具体项目的联系理由、待核问题和开发信内审稿 |
| CRM 与漏斗 | 当前阶段、负责人、复查条件，以及哪些证据足以推进商机 |

## 实操｜日本室内固装 LED 渠道开发

**商业目标：** 为小间距商显 LED 寻找日本本地集成合作方。终端场馆是应用方，做设计施工的集成商才是本轮需要研究的合作对象。谁选型、谁采购，要另行核对。

| 优先级 | 从公开资料观察到什么 | 销售判断 |
| --- | --- | --- |
| 优先核实 | 有室内常设项目，也有成熟的小间距产品线 | 有落地能力，但不能据此判断正在采购。先问项目规格或维护条件不匹配时，是否愿意评估外部备选。 |
| 保留备选 | 能做商业空间导视，也已建立供货和维护方案 | 只有能说明具体的规格差异或供货分工，才值得推进。 |
| 暂缓 | 公开案例明确使用既有设备品牌 | 不是排除整个公司；等出现品牌未定或有明确合作分工的新项目再查。 |

**交接结果：** 优先对象进入「研究完成／草稿待审」，不进入已接洽商机。销售负责人先核实对接职责和合作入口，再决定是否外联；只有获取明确的采购线索或客户实际行动，才按团队标准推进。未确认负责人或复查日期时，就留待分配，不假填。

**发信控制：** 公开研究和内审稿无需绑定邮箱。只有要在邮箱里存稿、查回信或发送时，才接入经授权的账号。发件身份、收件对象及稿件须在获准范围内；未确认发送，CRM 不写已发。这次实操没有绑定邮箱、发送邮件或查看回信。

案例来自一次真实的公开资料研究。企业、项目和个人身份、可反查细节及内部草稿均未公开；本页不提供完整 Skill 或安装包。
